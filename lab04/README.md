## Задание 1. Оболочка как язык склейки

| Команда | Класс (`type -a`) | Пакет (`rpm -qf`) |
|---|---|---|
| `cd` | встроенная | — |
| `echo`, `test` | встроенная, а также `/usr/bin/echo`, `/usr/bin/test` | coreutils |
| `ll` | псевдоним `ls -l` | — |
| `grep` | псевдоним `grep --color=auto` и `/bin/grep` | grep |
| `sed` | внешняя `/bin/sed` | sed |
| `mktemp` | внешняя `/bin/mktemp` | coreutils |

Переменная без `export` в дочерней `bash -c` пуста, после `export` — видна;
присваивание в дочерней оболочке на родителя не влияет (у дочернего процесса
своя копия окружения).

| Подстановка (`S=/usr/share/doc/lab04/report.tar.gz`) | Результат |
|---|---|
| `${S#*/}` — кратчайший префикс | `usr/share/doc/lab04/report.tar.gz` |
| `${S##*/}` — длиннейший префикс | `report.tar.gz` |
| `${S%.*}` — кратчайший суффикс | `/usr/share/doc/lab04/report.tar` |
| `${S%%.*}` — длиннейший суффикс | `/usr/share/doc/lab04/report` |

Перенаправления обрабатываются слева направо: `> f 2>&1` — сначала stdout в файл,
потом stderr туда же (в файле обе строки); `2>&1 > f` — stderr копирует ещё
старый stdout (терминал), в файл попадает только stdout. `ls /etc/hostname 2 > f`
без признака дескриптора — `2` становится аргументом `ls` («невозможно получить
доступ к '2'»), а в файл уходит stdout. `sources/pipeline.sh`: конвейер
`getent passwd | cut | sort | uniq -c | sort` с циклом `while read` и
проверкой `[ -x ]`, второй цикл читает встроенный документ `<<END`;
вывод совпадает с `check/expected-pipeline.txt`.

## Задание 2. Временные файлы и сигналы

`sources/tmpdemo.sh`: `mktemp`, `trap cleanup EXIT`, `trap 'exit 130' INT`,
`trap 'exit 143' TERM`. Имена уникальны; файл удаляется при штатном выходе
(код 0), ошибке (2), `kill -TERM` (143) и `^C` в псевдотерминале (130) —
наличие проверялось из другого процесса. Ожидание сделано `sleep & wait`, чтобы
сигнал обрабатывался сразу, а не после окончания `sleep`.

Права: файл `-rw-------` (600), каталог `drwx------` (700) — независимо от umask
0022, чтобы другие пользователи не могли прочитать или подменить файл.
В ALT `TMPDIR=/tmp/.private/user` (каталог 1770 root:user). `mktemp -u` печатает
имя без создания файла; шаблон `lab04-dzhakishev.XXXXXX`; минимум три `X`:
`mktemp lab.XX` — «слишком мало X в шаблоне».

## Задание 3. Обработка текстовых данных

Два набора из `ps -eo pid=,user=` и `ps -eo pid=,comm=`. При `ru_RU.UTF-8`
`sort` сравнивает строки по правилам локали, где пробелы почти не учитываются:
строка `   2986 root` оказывается раньше `    298 root`. `join` сравнивает уже
поле-ключ (`298` < `2986`) и сообщает `is not sorted`, код 1. С `LC_ALL=C`
сравнение побайтовое и согласованное, диагностики нет, 225 строк на 225 общих
идентификаторов. Использованы `cut`, `tr`, `head`, `tail`, `paste`, `uniq -c`.

Фрагмент `1 root systemd\n` одинаково показан `hexdump -C` (util-linux),
`od -t x1z` (coreutils) и `xxd` (xxd). `sort f > f` даёт пустой файл: оболочка
обрезает `f` до запуска `sort`; `sort f | sponge f` (moreutils) сначала читает
весь поток, потом пишет. Также применены `ts`, `ifne`, `chronic`.

## Задание 4. dzh-todo

Данные — `${XDG_CONFIG_HOME:-~/.config}/dzh-todo/tasks`, строки `0|текст` /
`1|текст`; каталог и файл создаются при первом запуске, существующий файл не
перезаписывается. Неинтерактивно: `add ТЕКСТ`, `list`, `done N`; последовательность
«3 × add, done 2, list» совпадает с `check/expected-todo.txt`. Без параметров —
меню `dialog --menu`, ввод `--inputbox`, список `--msgbox`, отметка `--checklist`.
dialog печатает выбор в stderr, он перенаправляется во временный файл (`2> "$tmp"`),
который удаляется обработчиком `trap`. Пункты checklist собираются в позиционные
параметры (`set -- "$@" "$n" "$text" off`) и передаются как `"$@"` — текст с
пробелами остаётся одним аргументом без `eval` и разбиения на слова.

## Задание 5. Пакет сценария

`specs/dzhakishev-todo.spec`: `Source0: dzh-todo`, `BuildArch: noarch`,
`install -D -m 0755 %SOURCE0 %buildroot%_bindir/dzh-todo`, без `Requires` и
`BuildRequires`. В журнале сборки:

```
find-requires: FINDPACKAGE-COMMANDS: cat clear dialog grep mkdir mktemp sed tr
Requires: /bin/sh, coreutils, dialog, grep, sed, termutils
```

Скрипт `shell.req` разбирает текст сценария, выделяет имена вызываемых внешних
команд, а `find-requires` находит пакеты, которые предоставляют эти команды в
окружении сборки; `/bin/sh` взят из строки `#!` (скрипт `shebang`). Пакет `dialog` при этом в
окружение не ставился — сборке он не нужен. Установка в окружение без dialog:
`dialog is needed by dzhakishev-todo-1.0-alt1`, код 1; после `hsh-install dialog` —
код 0, сценарий работает, вывод совпадает с эталоном.
